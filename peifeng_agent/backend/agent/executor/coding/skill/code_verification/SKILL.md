# 代码核验

**核验的敌人是"看起来对"**。以下七项都要给出**证据**（命令 + 输出），不能靠读代码推测。

## 一、七项核验（按这个顺序）

| # | 核验项 | 怎么验 | 不合格的样子 |
|---|---|---|---|
| 1 | 能跑通 | 用 `bash` 实际执行一次，看退出码 | 只贴了代码说"应该可以" |
| 2 | 结果正确 | 拿一份**能手工算的小样本**对照（3~5 行数据） | 只在大数据上跑，没人知道对错 |
| 3 | 失败显式 | 故意给错输入（文件不存在、字段缺失、类型不对），看是否报错且信息可读 | 静默跳过、`pass`、返回空列表 |
| 4 | 边界处理 | 空文件、只有表头、缺列、负值/0、超长行、编码（GBK/BOM）各试一次 | 遇到空文件直接崩，或把空当成功 |
| 5 | 幂等可重跑 | 连跑两次，第二次结果与第一次一致、不重复追加 | 第二次跑出两份数据 |
| 6 | 依赖可用 | 确认 import 的库在**当前机器**装得上（`bash python -c "import x"`） | 用到没装的库，跑起来才报错 |
| 7 | 无破坏性副作用 | 检查是否改了源文件、是否删了东西、是否写到项目外 | 直接原地覆盖输入数据 |

## 二、产出：核验报告（写进 content 或落盘）

```
核验结论：通过 / 不通过（哪一项不过）

1. 跑通：`python clean.py` → 退出码 0，输出「4120 行」
2. 结果：手工算 3 行样本 = 32700，脚本输出 32700 ✅
3. 失败：给不存在的文件 → 报「FileNotFoundError: 输入文件不存在: x.csv」✅
4. 边界：空文件 → 报「没有数据行」✅；GBK 编码 → 正常解析 ✅
5. 幂等：连跑两次，输出文件大小与行数一致 ✅
6. 依赖：pandas 未安装 → 改用 csv 标准库 ✅（或明确写"需要用户安装 pandas"）
7. 副作用：只写了 out/ 下的新文件，源数据未改动 ✅
```

## 三、三条硬约束

1. **自己跑过才算通过**：没有执行记录的"通过"是主张，不是证据。
2. **样本要小到能手算**：三行数据的对错能一眼看出；一万行看不出。
3. **失败也要记**：哪一项没过、为什么、建议怎么改——比"全部通过"有用得多。

## 四、常见误判

- 脚本没报错 ≠ 结果对（可能静默丢了 500 行）
- 在大数据上跑通 ≠ 边界处理了（可能只是没碰到空值）
- 读过代码 ≠ 跑通过（缩进、编码、路径都可能出问题）
